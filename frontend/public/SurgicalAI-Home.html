How it works

Two agents.
One source of truth.

Every change passes through a strict four-stage pipeline. No shortcuts, no guessing.

1

Architect plans the change

Claude reads your request, identifies the exact symbol and line range, and decides whether to route to the Surgeon or trigger a full rewrite.

Claude — Architect
2

Size-based routing

Small, focused changes (<250 lines) go to the Surgeon for SEARCH/REPLACE. Large multi-region changes go direct at 32K tokens.

Auto-routed
3

Surgeon applies the operation

The Surgeon operates on a focused window of the live file — never a stale copy. SEARCH strings are validated before any change is committed.

Claude — Surgeon
4

QA auto-heals on failure

TypeScript is compiled after every change. Any error triggers up to 3 auto-heal attempts — Claude sees the fresh error output and the live file each time.
